When the same column contains grams and milliliters

Greggs labels its shared portion-size column “g/ml.” A numeric entry alone does not say which unit belongs to that row. If a source independently states nutrition per 100 g, that published value can be useful even when GetMacros cannot confirm the unit of the portion-size entry. The table only counts normalized fields in the local registry. It does not count every comparison you could make by consulting the underlying document.

How a confirmed weight changes the comparison

Suppose a sandwich is 340 kcal per 200 g and another is 300 kcal per 150 g. The first is 170 kcal per 100 g, and the second is 200 kcal per 100 g. The lighter sandwich has fewer calories in the complete order. The first sandwich has fewer calories at equal weight. The numbers in this example are illustrative.

Why this is a data coverage count

Each tracked UK row counts once, including sizes, drinks, sides and ingredients when the source supplies them as separate rows. A positive numeric servingGrams is required, and a value in milliliters is never converted to grams here. A chain with an empty weight column may still give nutrition per order. These counts describe the registry and should not be used to rank restaurants by the quality or completeness of their live menus.
